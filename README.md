# DayOut — AI-помощник для городского досуга

DayOut помогает выбрать места для прогулки, свидания или встречи. Пользователь описывает пожелания обычным текстом и уточняет их по ходу разговора. Агент ищет места в Google Maps, получает прогноз погоды и проверяет пешие маршруты. Ответы сопровождаются ссылками и указанием неизвестных данных.

**[Открыть приложение](https://dayout-ai-agent.streamlit.app/)** · **[HTML-презентация](https://batyaoftheyear.github.io/DayOut-AI-agent/presentation.html)** · **[PDF-презентация](docs/DayOut-presentation.pdf)**

Стек: Python · Streamlit · Alice AI LLM Flash в Yandex AI Studio · официальный Google Maps MCP.

## Пользователь и сценарий

Для человека, который планирует досуг и хочет сравнить несколько вариантов с учётом района, интересов, компании и бюджета. Основная область проверки — Москва.

Пример последовательности запросов:

> «Подбери два уютных кафе в центре Москвы. Нас двое, общий бюджет 3000 рублей».
>
> «Лучше в Нагатино, грузинская кухня».
>
> «Проверь погоду в Москве на завтра».

Это пример использования, а не сохранённая выдача. Конкретные места и доступные сведения зависят от ответа API.

## Границы MVP

- Поиск мест и сведений о них; уточнения и смена условий в разговоре.
- Сохранение суммы, валюты, числа участников и единицы бюджета.
- Текущая погода и прогноз в пределах доступного горизонта API.
- Пешие и автомобильные маршруты; проверка явно заданного пешего предела.
- Определение Place ID по названию и ссылке Google Maps.

Система не бронирует столики, не продаёт билеты и не хранит постоянный профиль пользователя. Полный чек, свободные места, актуальная выставочная программа и субъективная атмосфера не гарантируются. Другие города можно искать, но полнота оценки за пределами Москвы ограничена.

Критерии готовности: публичный интерфейс, работающая LLM–MCP-интеграция, ссылки на источники, воспроизводимый запуск и Eval с опубликованным разбором ошибок. Используется готовый официальный MCP-сервер Google; собственный сервер не разрабатывался.

## Архитектура

```mermaid
flowchart LR
    U[Пользователь] --> W[Streamlit / CLI]
    W --> A[Python-агент]
    A <--> L[Yandex AI Studio: Alice Flash]
    A <--> M[MCP Python SDK]
    M <--> G[Google Maps MCP]
    A --> V[Проверка параметров, ссылок и маршрутов]
    V --> W
```

Streamlit Community Cloud размещает Python-приложение. Модель и Maps доступны через внешние API; GPU на хостинге не нужен. Разговор хранится в памяти сеанса. Разные сеансы не разделяют историю. Одновременно в одном процессе выполняется один пользовательский запрос.

Основные модули: `app.py` — интерфейс; `web_backend.py` — сеансы и подключения; `agent.py` — цикл инструментов и проверки; `conversation_context.py` — условия разговора; `yandex_client.py` — адаптер модели; `geo.py` — расчёты по координатам и длительности; `eval_runner.py` — оценка.

## MCP-интеграция

Сервер: `https://mapstools.googleapis.com/mcp`. Транспорт: Streamable HTTP. Приложение получает инструменты через `initialize` и `tools/list`, а затем выполняет `tools/call`. Ключ передаётся с сервера приложения в заголовке `X-Goog-Api-Key`.

| Инструмент | Назначение |
| --- | --- |
| `search_places` | Найти места или проверить конкретное свойство: цены, часы, доступность |
| `lookup_weather` | Получить текущую погоду, дневной или почасовой прогноз |
| `compute_routes` | Получить расстояние и длительность пути |
| `resolve_names` | Определить Place ID по названию или адресу |
| `resolve_maps_urls` | Определить Place ID по ссылке Google Maps |

Входные схемы сервера загружаются через MCP. Адаптер упрощает работу модели с точками: метка найденного места преобразуется в подтверждённый Place ID для маршрута или координаты для поиска рядом. Перед отправкой параметры проверяются по исходной схеме Google. Модель не должна копировать длинные идентификаторы или придумывать координаты.

## AI-логика

1. Модель получает связный диалог и все пять инструментов. Она выбирает поиск, уточнение, другой инструмент или готовый ответ. Предварительного классификатора, разрешающего инструменты по типу запроса, нет.
2. Python проверяет и исполняет настоящий `tool_call`. Результат и источники возвращаются модели; цикл продолжается до ответа.
3. Отдельный короткий запрос сохраняет условия из реальных сообщений пользователя. Он не составляет план и не отдаёт команды основному агенту. Пожелания хранятся свободным списком, без отдельных полей для каждой кухни или атмосферы.
4. Приложение проверяет ссылки, служебный текст и явные ограничения. При исправимой ошибке модель получает обратную связь и сохраняет доступ к инструментам. Текст функции или JSON сам по себе не исполняется.

В памяти сохраняются до 20 завершённых ответов, соответствующие пользовательские реплики и ограниченный объём данных инструментов. После неудачного ответа пользовательское уточнение сохраняется; отвергнутый текст модели не становится подтверждённым фактом. На один ход предусмотрено до 8 реальных MCP-вызовов и 120 секунд. Повторный запрос того же маршрута в рамках хода использует уже полученный результат.

### Бюджет и близость

В `search_places` нет обязательного поля среднего чека и отдельного фильтра по бюджету. Целевой запрос о заведении может вернуть диапазон расходов в текстовой сводке. Агент должен учитывать единицу диапазона и число людей. Например, если получено **3000–8000 ₽ на человека**, то для двоих нижняя граница 6000 ₽ превышает общий бюджет 5000 ₽. Это пример расчёта, а не актуальная цена конкретного заведения.

Если после целевого запроса цены не получены, попадание в бюджет остаётся неподтверждённым. Диапазон расходов посетителей не равен вычисленному среднему чеку или гарантии стоимости заказа.

Пеший предел подтверждается маршрутом, а не расстоянием по прямой: 632 секунды превышают 10 минут. Для строгого предела Python может дополнительно проверить до трёх кандидатов из той же выдачи. При мягком «рядом» поиск можно расширить с явным указанием более долгого пути. Для обычного поиска по району искусственный пеший предел не добавляется.

## Локальный запуск

Python 3.11 или 3.14. Версии зависимостей закреплены.

```powershell
git clone https://github.com/Batyaoftheyear/DayOut-AI-agent.git
cd DayOut-AI-agent
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполнить `.env`:

```dotenv
LLM_PROVIDER=yandex
YANDEX_API_KEY=your-yandex-key
YANDEX_FOLDER_ID=your-folder-id
YANDEX_MODEL=aliceai-llm-flash
GOOGLE_MAPS_API_KEY=your-maps-key
```

Нужны активный платёжный аккаунт Yandex Cloud, ключ с правом генерации и собственный доступ к Maps Experience agent tools. Квоты и биллинг сервисов независимы. Секреты не добавляются в Git.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Открыть `http://localhost:8501`. Консоль: `python dayout.py --usage`; команды `/check`, `/retry`, `/reset`, `/exit`. `--usage` показывает токены. [Настройка Yandex AI Studio](docs/yandex.md).

## Развёртывание

В Streamlit Community Cloud выбрать этот репозиторий, ветку `main`, Main file path **`app.py`**. В Settings → Secrets задать параметры из `.streamlit/secrets.toml.example`, включая `YANDEX_MODEL = "aliceai-llm-flash"`. Локальный `.env` на хостинг не загружается.

После изменения Secrets перезапустить приложение и начать новый диалог. Приоритет: окружение процесса → Streamlit Secrets → `.env`. Неактивное бесплатное приложение может засыпать. [Подробная инструкция](docs/deployment.md).

**Завершение не равно качеству.** Программа проверяет инструменты, аргументы, даты и сохранение условий. Отдельный запрос к той же модели оценивает содержание по исходным данным MCP. Это модельная оценка с возможными ошибками, не независимая экспертная разметка. Первые неуспешные попытки сохраняются. Отказы сети и API учитываются в сквозном результате.

| Ограничение | Как обрабатывается |
| --- | --- |
| Не хватает цен, часов или других свойств | Целевой запрос к источнику; при отсутствии данных явная оговорка |
| Уточнение меняет район, кухню или бюджет | Продолжение по диалогу с сохранением применимых условий |
| Получен JSON вместо действия | Служебный текст блокируется, допускается исправление настоящим вызовом |
| Кандидат не проходит пеший предел | Проверка реального маршрута, исключение слишком дальнего варианта |
| Модель добавляет неподтверждённые сведения | Программные проверки и отдельная оценка содержания; универсальной гарантии нет |
| Сеть, квота или генерация недоступны | Понятное сообщение и возможность повторить; ошибка не заменяется выдуманными данными |

259 технических тестов проходят без внешних API. Они не заменяют живой Eval.

## Данные

Ключи используются на сервере. Постоянной базы разговоров нет. Данные Maps и диалог находятся в памяти сеанса; в публичных отчётах сохраняются метрики и категории ошибок, без сырых ответов Maps. Запросы к модели передаются с `x-data-logging-enabled: false`; это не универсальная гарантия отсутствия хранения или кэширования у провайдера.
