# DayOut

Учебный AI-ассистент для персонализированного планирования досуга.
Текущий этап — веб-чат Streamlit и консольный агент: **Yandex Alice Flash → Google Maps Grounding Lite MCP → ответ**.
Groq сохранён для явного переключения через конфигурацию.
Есть диалог в памяти процесса, динамические инструменты, проверка аргументов
и лимиты. Сервис размещён на [Streamlit Cloud](https://dayout-ai-agent.streamlit.app/).
Подготовлен Eval из 30 живых сценариев; полный прогон после исправлений и HTML-презентация ещё не завершены.

Репозиторий: [Batyaoftheyear/DayOut-AI-agent](https://github.com/Batyaoftheyear/DayOut-AI-agent).

## Веб-интерфейс

После установки зависимостей и заполнения `.env`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте `http://localhost:8501`. Напишите запрос или выберите пример, затем уточняйте
пожелания обычным текстом. Кнопка «Новый диалог» очищает контекст текущего сеанса.
Ссылки Google Maps показаны рядом с рекомендациями, время/токены — в деталях ответа.
При сетевом сбое модели нажмите «Проверить связь», затем «Продолжить запрос».
При остановке из-за квоты дождитесь указанной паузы и нажмите «Продолжить запрос».

История и незавершённый ход находятся только в памяти отдельного сеанса браузера;
при обновлении страницы/перезапуске сервиса они могут потеряться. Между перезапусками
скрипта сохраняются только данные, а HTTP/MCP-подключения создаются заново и закрываются
в рамках того же async-вызова. В общем кэше нет разговоров или ответов Maps:
там только блокировка и числовые счётчики общей квоты.

Демо принимает один запрос одновременно на процесс, с интервалом не меньше 5 секунд
между началами запросов. Это простая защита общей квоты, а не распределённый лимитер
или гарантия доступности при любой нагрузке. Неотправленный из-за занятости запрос
можно повторить кнопкой без нового ввода.

Для хостинга точка входа — **app.py**. Ключи читаются из переменных окружения,
затем Streamlit Secrets, затем локального `.env`. Настоящий `secrets.toml` исключён
из Git. Пошаговая инструкция: [развёртывание на Streamlit](docs/deployment.md).

Технические проверки охватывают интерфейс, изоляцию сеансов, закрытие клиентов,
бюджет и смену категории, фильтрацию источников, квоты и ручное продолжение.
Они используют искусственные ответы и не измеряют качество реальных рекомендаций.
Ранее поиск с Яндексом проходил через CLI и локальный веб-адаптер; после новой
стадии планирования нужен отдельный живой пилот. [Методика Eval](docs/evaluation.md).

При локальной разработке обнаружена причина постоянных сетевых ошибок MCP:
Streamlit был запущен инструментом разработки в сетевой песочнице. После перезапуска
процесса с доступом к сети поиск через сам браузер прошёл с двумя ссылками Maps.
Для самостоятельного запуска используйте обычный терминал; подробности в
[инструкции](docs/deployment.md). Ошибки MCP теперь показывают безопасный тип
сетевого сбоя; конкретная причина других отказов требует отдельной диагностики.

## Запуск в Windows PowerShell

Нужен Python 3.11+. Локально окружение создано на Python 3.14.4.
Команды выполняются из директории проекта; активация окружения не требуется.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

Если `.env` уже существует, сохраните его. Откройте его локально и заполните
`GOOGLE_MAPS_API_KEY` своим Google Maps Demo Key. Не присылайте ключ в чат.
Существующая переменная окружения имеет приоритет над `.env`.

Текущий провайдер — Yandex AI Studio, модель `aliceai-llm-flash`.
В `.env` задайте `LLM_PROVIDER=yandex`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`
и `YANDEX_MODEL=aliceai-llm-flash`. Проверка подключения:
`.\.venv\Scripts\python.exe yandex_check.py` (три небольших платных запроса,
искусственный инструмент, без Maps). Подробности — [подключение Яндекса](docs/yandex.md).
Для явного возврата на Groq задайте `LLM_PROVIDER=groq`, `GROQ_API_KEY`,
`GROQ_MODEL`; для Groq ранее был включён Global ZDR.
Автоматического переключения провайдера, модели или тарифа нет.

```powershell
# Основной консольный чат: вводите запросы и уточнения обычным языком
.\.venv\Scripts\python.exe dayout.py

# Дополнительно показывать расход каждого обращения к LLM
.\.venv\Scripts\python.exe dayout.py --usage

# Один запрос, затем выход
.\.venv\Scripts\python.exe dayout.py --query "Найди два музея Москвы и дай ссылки Google Maps"

# Запрос и уточнение в одной сессии
.\.venv\Scripts\python.exe dayout.py --query "Найди два музея Москвы" --query "Выбери из них один для любителя живописи"
```

В активированном окружении можно использовать `python dayout.py`.
Команды чата: `/reset` очищает контекст, `/exit` завершает программу,
`/check` проверяет доступ к выбранному провайдеру, `/retry` повторяет последний неудачный запрос.
После строки `MCP → search_places` виден фактический вызов, выбранный моделью.
Сырые схемы и ответы инструментов в чате не печатаются. В конце каждого ответа
показываются число попыток вызова инструментов, время и суммарные входные/выходные
токены, сообщённые API модели. Если API не вернул usage, это отмечается явно.

## Как работает агент

```text
Запрос/уточнение → LLM-план условий (Яндекс) → LLM: выбор инструмента
→ проверка имени, JSON Schema и отдельных ограничений
→ Python MCP SDK → Google Maps MCP → данные инструментов → LLM → ответ со ссылками
```

- Инструменты и схемы получает `list_tools()`. LLM доступны только пять разрешённых
  инструментов Maps; Python исполняет вызовы, модель сама выбирает действия.
- Не более 8 попыток вызова инструментов за ход и 120 секунд на попытку обработки,
  включая ожидание квот. Ручное продолжение сохраняет лимит шагов и MCP-вызовов.
  Подключение/получение схем отдельно ограничены 60 секундами; HTTP-запросы — 45.
- В контекст входят запросы пользователя без пересказа, два последних ответа и
  данные последнего из этих ходов с результатами инструментов. Старые служебные
  tool_calls повторно не отправляются. Условия сохраняются до суммарных 12 000
  символов пользовательских запросов; при превышении нужен `/reset`, а не молчаливое
  удаление условий. Память не записывается на диск.
- Внутри запросов длинные исходные URL заменяются короткими метками источников.
  Приложение разворачивает их в неизменённые ссылки Google Maps перед выводом;
  неизвестные метки блокируются. Источники и Place ID сохраняются.
- Поиск по умолчанию запрашивает 3 места, если реальная схема поддерживает pageSize
  и модель не указала количество явно. Ответ модели ограничен 1600 токенами;
  инструкция просит до 150 слов. Язык поиска — ru, если реальная схема поддерживает
  languageCode/language_code и модель не указала его явно. Обрезанный ответ не выдаётся за завершённый.
- При сбое незавершённый ход не попадает в историю; прошлые успешные ходы сохраняются.
- Внешние ответы считаются данными, а не инструкциями. Неизвестные инструменты и
  неверные аргументы не исполняются; модель может исправить их в пределах лимита.
- Яндекс сначала формирует структурированный план: цель, район, категория, бюджет
  и необходимые инструменты. Это дополнительное платное обращение LLM на ход,
  включённое в usage и время. Для Groq эта стадия пока отключена. План может
  ошибиться; он не заменяет оценку ответов.
- При новом поисковом намерении агент требует фактическую попытку вызова.
  Python добавляет условия и сохранённый бюджет в текст search_places. При
  отсутствии цен разрешён один уточняющий поиск; без данных попадание
  в бюджет не гарантируется. Если бюджет не задан, шаблон о нём не нужен.
- После успешной пустой выдачи допустим один поиск рядом с исходным районом,
  кроме явного запрета пользователя; расширение должно быть раскрыто.
- Ссылки проверяются по источникам текущей задачи. Общая беседа и объяснение
  ошибки не получают старый список мест. Источники не добавляются автоматически.
  Неизвестные метки/URL блокируются. Для Яндекса допускаются до двух исправлений
  разных дефектов, повтор того же дефекта останавливает ход; для Groq — одно.
  Непроверенный текст не выдаётся пользователю и не становится доказательством.
- Проверяются отдельные обещания фоновой проверки, часы без данных и минуты
  пути без compute_routes. Для погоды дополнительно проверяются один способ
  задания location, полная календарная дата, hour с датой и диапазон 0–23.
  Эти ограничения не доказывают правильность фактов, района или расписания
  каждого места. Для этого требуется ручная сверка по MCP в Eval.
- Для погоды не отправляется необязательный languageCode: в сравнительных
  проверках текущего ключа его явное задание приводило к отказу доступа, а
  тот же запрос без поля проходил. Ответ локализует LLM. Успешный пустой
  search_places `{}` считается пустой выдачей, а не ошибкой сервиса.

Бесплатный Groq ограничивает не только количество запросов, но и токены в минуту.
Один ход чата может вызвать несколько запросов модели. При известных заголовках
лимита агент ожидает сброса окна перед следующим запросом (об этом есть сообщение).
Оценка размера калибруется по фактическому usage последних запросов, но остаётся
приблизительной: HTTP 429 всё равно возможен. HTTP- и сетевые ошибки не
повторяются автоматически. Ожидание входит в общий таймаут попытки, а квоты делятся со
всеми клиентами вашей организации. Большие ответы/история могут не поместиться
в бесплатный лимит — сократите запрос или очистите диалог.

Суммарное автоматическое ожидание квоты ограничено **45 секундами за попытку**.
Если очередная пауза не помещается в этот бюджет, HTTP-запрос не отправляется:
ход сохраняется для `/retry`, а найденные кандидаты показываются по метаданным
MCP без неподтверждённого описания. После указанной паузы можно ввести `/retry`
без `/check`. Если общий таймаут сработал при ожидании LLM, когда все MCP-вызовы
уже завершены, такое продолжение тоже сохраняется. При HTTP 429 состояние
сохраняется, но расход отклонённого запроса без usage остаётся неизвестным.

Обычный поиск мест без даты должен начинаться с `search_places`. Погода запрашивается
по просьбе пользователя или для уличного плана на конкретный день;
сама текущая дата в системном сообщении не означает посещение сегодня. Это инструкция
LLM, её соблюдение проверяется в Eval.
Условие «холодно, хочу в помещении» используется как готовое предпочтение без
дополнительного прогноза. Для новых часов визита модель должна включить время и
часы работы в поисковый запрос, а при отсутствии сведений сообщить неизвестность.

При HTTP 400/404 показывается расшифровка известного кода API, например
`tool_use_failed`. Содержимое `message` и `failed_generation` не выводится: оно может
содержать запрос и данные инструментов. Для неизвестного кода причина явно обозначается
как неустановленная. Старое общее сообщение про ID модели не позволяло установить
причину уже произошедших отказов. Автоматического повтора таких запросов нет.

Текущий CLI предназначен для локальной разработки, не для публичного многопользовательского сервиса.

### Если диалог остановился из-за сети или HTTP 403

`ConnectError` означает ошибку установления соединения, `ProxyError` — ошибку
прокси, `ReadError` — обрыв получения ответа. HTTP 403 означает запрет доступа;
по одному статусу нельзя установить блокировку аккаунта или региона. HTTP 429
обозначает превышение квоты и обрабатывается отдельно.

После сетевого сбоя Groq или HTTP 401/403 чат приостанавливает отправку новых
вопросов. Проверьте свою сеть и настройки доступа, затем введите `/check`.
Команда делает два запроса: список моделей и генерацию с фиксированным техническим
текстом. Переписка и данные Maps в этой проверке не отправляются. Если проверка
успешна, введите `/retry` или новый вопрос. При сбое обращения к Groq незавершённый
ход сохраняется отдельно от успешной истории, только в памяти процесса. В течение
5 минут `/retry` продолжает его с полученными MCP-результатами. Счётчики MCP-вызовов,
шагов и исправлений сохраняются; модель всё ещё может запросить дополнительные данные.
Сохранённый ход не возобновляется автоматически. Новый вопрос, `/reset` или перезапуск
удаляет его; после истечения 5 минут `/retry` начинает ход заново. При сбое самого MCP
продолжение не сохраняется, чтобы не восстанавливать неполный протокол tool_calls.
Прошлые успешные ходы остаются в памяти до `/reset` или завершения процесса.

Итог возобновлённого хода включает известный расход и MCP-вызовы предыдущей попытки,
но исключает `/check`; расход попыток без usage отмечается как неизвестный. Время
включает обе попытки обработки, без ожидания пользовательского ввода и `/check`.

В строке `Вы:` вводите только вопрос. Не вставляйте туда весь вывод терминала:
каждая вставленная строка может восприниматься как отдельный ввод. Пустые строки,
неизвестные команды и распознанные строки лога (`Вы:`, `DayOut:`, `MCP →`,
`Groq:` и другие служебные префиксы) не отправляются модели. Эта проверка
распознаёт известные префиксы, а не произвольный текст любой переписки.

После изменения кода завершите старый процесс через `/exit` или Ctrl+C и
запустите `dayout.py` заново: уже работающий процесс сам код не перечитывает.

## Eval и разбор ошибок

Набор `eval/cases.json`: **30 живых сценариев / 37 ходов**, включая все пять
инструментов, бюджет на всех/человека/час, смену категории и темы, погоду,
маршрут и комбинированный план. 20 сценариев предназначены для настройки,
10 — для итоговой проверки. Отдельно четыре искусственные проверки сбоев.

Автоматические проверки оценивают вызовы и наблюдаемые нарушения. Релевантность,
условия, правдивость и опору на MCP размечает человек. Отказы сервиса считаются
отдельно; они остаются неуспехами сквозной системы. Сырые ответы Maps в отчёт
не записываются. Запуск ограничен пятью пользовательскими ходами по умолчанию;
живой режим платный, цены и денежный порог задаются явно.

**Результаты проверок 29 октября:** технические проверки проходят;
четыре искусственных сценария — в [отчёте без внешних запросов](eval/results/offline-current-2026-10-29.json).
29 октября прямой lookup_weather для Москвы на 30 октября вернул isError=false;
LLM не вызывалась в прямой проверке. В [последнем разработческом пилоте](eval/results/pilot-mvp-2026-10-29.json)
завершились оба сценария / три хода: кафе → бани с сохранением 4000 ₽ на двоих
и отдельная погода. Расход этого пилота: 9 обращений LLM, 18 425 входных и
813 выходных токенов. В нём осталась противоречивая фраза о попадании в бюджет
при неизвестных ценах; после пилота добавлены инструкция и локальная проверка
такого противоречия. Успешный повтор этой последней правки с API ещё не выполнен.
Полного живого Eval новой версии пока нет, процент качества
и стоимость полного прогона не измерены. Исходный коммит записан в
`eval/baseline.json`; его качество тоже не измерялось.

| Наблюдавшийся дефект | Изменение | Статус |
| --- | --- | --- |
| Отказ искать бани после кафе | План нового намерения + требование нового вызова | Новый поиск и сохранение бюджета прошли в живом пилоте; полезность требует разметки |
| Бюджет терялся в поиске | Сохранение суммы/единицы, добавление в запрос, уточнение цен | Проверена передача условий; истинность цен требует Eval |
| Старые кафе в ответе о погоде/общем вопросе | Источники текущей задачи, без автоматического каталога | Искусственный диалог пройден |
| Пустая выдача завершала поиск | Одна попытка рядом, если район не строгий | Искусственные варианты проверены |
| Погода/HTTP 400 | Проверки аргументов; исключение languageCode; отдельные статусы ошибок | Погода проходила напрямую и через LLM; прежняя причина HTTP 400 не установлена |

[Методика, критерии и команды](docs/evaluation.md),
[журнал наблюдавшихся ошибок](docs/error-analysis.md),
[оставшиеся задачи к защите](docs/mvp-readiness.md).
Согласование темы с преподавателем пользователь пока не подтверждал.

## Отдельные диагностические скрипты

```powershell
# Только список инструментов и реальные входные JSON-схемы
.\.venv\Scripts\python.exe mcp_check.py --list-only

# Схемы и один тестовый поиск музеев Москвы
.\.venv\Scripts\python.exe mcp_check.py

# Другой запрос и общий таймаут
.\.venv\Scripts\python.exe mcp_check.py --query "Музеи Москвы, Россия" --timeout 90

# Локальные тесты без Google Maps и без ключа
.\.venv\Scripts\python.exe -m pytest -q
```

Скрипт выполняет `initialize()`, `list_tools()` (с учётом страниц), выводит
реальные `inputSchema`, проверяет аргументы по полученной схеме и вызывает
`search_places`. Поддерживаются названия полей `text_query`/`textQuery` и
`language_code`/`languageCode`; несовместимая схема останавливает поиск.
Результат выводится целиком вместе с возвращёнными источниками и атрибуцией.
Это диагностический CLI, а не готовый интерфейс рекомендаций.

Коды завершения: `0` — операция выполнена; `1` — ошибка проверки; `2` — ошибка
аргументов CLI; `130` — прерывание пользователем. Успешный `--list-only` проверяет
только получение схем. Успешный поиск не гарантирует непустого списка мест:
содержимое ответа нужно проверить отдельно.

## Ошибки и безопасность

- Без ключа скрипт завершится до сетевого подключения. Фиктивный ключ не используется.
- При HTTP 401/403 проверьте ключ, его ограничения и доступ к Maps Grounding Lite.
- HTTP 429 означает превышение квоты; автоматических повторов нет.
- Общий таймаут по умолчанию 60 секунд; допустимый диапазон — больше 0 и до 300.
- Сообщения SDK и HTTP-клиента отключены, traceback и тела ошибок не выводятся.
  Значение ключа скрывается также в штатном выводе.
- `.env`, окружение и логи исключены из Git. Ответы Maps не записываются на диск.
- Платные сервисы и биллинг не подключаются. Для тестирования используется Demo Key.

Реальное подключение и получение схем подтверждены в ходе работы над проектом.
В присланном пользователем выводе `search_places` вернул пять мест и
`isError: false`. Это подтверждает один успешный поиск; стабильность сервиса,
погода и расчёт маршрутов пока не проверены. Локальные тесты используют подмены:
Это отдельная техническая проверка интеграции; она не заменяет Eval рекомендаций.

## Проверка LLM через Groq

В локальном `.env` задайте `GROQ_API_KEY` и `GROQ_MODEL` (пример в `.env.example`).
Ключ Google Maps и ключ Groq — разные настройки. Существующие переменные
окружения имеют приоритет над `.env`. Дополнительные библиотеки не требуются:
используется уже установленный `httpx`.

```powershell
# Авторизация и реальные идентификаторы моделей, без генерации
.\.venv\Scripts\python.exe groq_check.py --list-models

# Список моделей и два запроса генерации на искусственных данных
.\.venv\Scripts\python.exe groq_check.py
```

Скрипт обращается к Groq Chat Completions API. Первый запрос предлагает модели
самостоятельно выбрать `get_demo_activity`. Код проверяет имя инструмента и
аргументы по JSON Schema, возвращает вымышленную активность с кодом DEMO-42.
Второй запрос проверяет, что модель использовала результат и ответила по-русски.
Это небольшая техническая проверка tool calling, а не Eval качества планировщика.

Если GROQ_MODEL нет в реальном списке, генерация не выполняется. Скрипт не
меняет модель автоматически. Наличие ID в списке не гарантирует бесплатный
доступ: проверьте тариф и лимиты своего аккаунта. Два запроса расходуют квоту;
автоматических повторов и переключения тарифа нет. HTTP 401/403, 400/404, 429,
сетевые ошибки и таймауты выводятся без ключей и тел ответов ошибок.
Таймаут — 45 секунд на HTTP-запрос, максимум три последовательных запроса.

Проверка 26 октября 2026 года: `qwen/qwen3.8-27b` найдена в API, выбран тестовый
инструмент с правильными аргументами, финальный ответ содержит DEMO-42 и русский
текст. Google Maps в этой проверке не вызывался. Сетевые проверки запускаются отдельно от pytest.

27 октября 2026 года пользователь подтвердил включение **Global Zero Data Retention**
в Groq. Код не может независимо проверить эту настройку по API-ключу.
Первоначально была выбрана `qwen/qwen3.8-27b`, которая не входила в список
моделей с prompt caching. После исчерпания её суточной квоты пользователь
выбрал `openai/gpt-oss-120b`. Для GPT-OSS настроены `reasoning_effort=low`
и `include_reasoning=false`; неявный кэш Groq для этой модели допускается
кодом, его нельзя отключить. Global ZDR не означает отсутствия такого кэша.
Это техническая адаптация, а не подтверждение совместимости кэширования
провайдера с условиями Google Maps. Подробности и результаты проверок —
в [docs/model-migration.md](docs/model-migration.md).
У Qwen прежняя остановка при неожиданном `cached_tokens > 0` сохранена.
Автоматического переключения модели/тарифа нет.
Не загружайте результаты Maps в Batch, Fine-tuning, постоянные логи и датасеты.

[вызовы инструментов](https://console.groq.com/docs/tool-use/local-tool-calling),
[обработка данных/ZDR](https://console.groq.com/docs/your-data),
[кэширование](https://console.groq.com/docs/prompt-caching).
