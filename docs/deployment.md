# Запуск и размещение веб-версии DayOut

Входной файл: `app.py`. Репозиторий пользователя:
[Batyaoftheyear/DayOut-AI-agent](https://github.com/Batyaoftheyear/DayOut-AI-agent).
Для деплоя в выбранной ветке должна находиться актуальная версия приложения.
Публичный URL сервиса появится после успешного размещения.

## Локальная проверка

Из корня папки DayOut:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Открыть `http://localhost:8501`. Если `.env` уже заполнен для консольного агента,
дополнительные локальные ключи не нужны. Приоритет настроек: переменные окружения →
Streamlit Secrets → `.env`; окружение процесса не перезаписывается приложением.
Текущая модель — `openai/gpt-oss-120b`, Global ZDR в Groq ранее подтверждён
пользователем. У GPT-OSS есть автоматический кэш провайдера; см.
[особенности перехода](model-migration.md). Настройка `.env` не изменяет Secrets
уже развёрнутого сайта.

Запускайте сервер из обычного PowerShell/терминала с доступом к сети. Сервер,
запущенный инструментом разработки внутри сетевой песочницы, может открыть
локальную страницу, но блокировать все исходящие подключения к MCP. При разработке
наблюдалась именно эта причина: одинаковый запрос падал в ограниченном процессе
и проходил вне него. После перезапуска сервера с доступом к сети реальный запрос
через страницу завершился с двумя ссылками Google Maps. Для такой ошибки не нужно
менять ключи или текст запроса; сначала проверить среду запуска процесса.

## Streamlit Community Cloud

1. В выбранной ветке GitHub должны быть текущие `app.py`, `web_backend.py`,
   `agent.py`, `dayout.py`, `groq_check.py`, `mcp_check.py`, `requirements.txt`,
   `assets/style.css` и `.streamlit/config.toml`. Загружать `.env`, настоящий
   `secrets.toml`, `.venv` и временные файлы не требуется.
2. В Community Cloud подключить GitHub и выбрать **Create app** → приложение
   из существующего репозитория.
3. Repository: `Batyaoftheyear/DayOut-AI-agent`.
4. Branch: ветка, в которую загружена веб-версия (например, `main`, если она так называется).
5. Main file path: `app.py`.
6. В **Advanced settings** выбрать Python **3.14** для соответствия локально
   проверенной версии. Linux-окружение хостинга проверяется при первом деплое.
7. В **Secrets** вставить TOML с собственными значениями:

```toml
GROQ_API_KEY = "your-groq-api-key"
GOOGLE_MAPS_API_KEY = "your-google-maps-api-key"
GROQ_MODEL = "openai/gpt-oss-120b"
```

8. Нажать **Deploy**, дождаться установки зависимостей и открытия страницы.
9. Скопировать фактический URL сервиса в README. Не подставлять выдуманный URL.

Шаблон этих настроек — `.streamlit/secrets.toml.example`. Настоящие ключи вставляются
в настройки хостинга самим владельцем аккаунта. Для отправки изменений используйте
отдельную копию репозитория DayOut. В репозиторий входят только файлы проекта,
без локальных ключей, виртуального окружения и содержимого домашнего каталога.

## Что проверить после деплоя

- Страница открывается в отдельном браузере и на телефоне.
- Обезличенный технический поиск даёт ответ и ссылку Google Maps: так проверяется
  исходящий доступ хостинга к Groq и Google Maps MCP.
- Уточнение сохраняет район/другие условия; два браузерных сеанса не смешивают историю.
- «Новый диалог», проверка связи и продолжение запроса работают.
- При ожидании квоты/сбое показывается понятное сообщение; ключи не выводятся.

Первый публичный деплой ещё не проверен. Локальный успешный поиск не доказывает
доступность API с хостинга. Бесплатные квоты провайдеров сохраняются и на сервере.
Ограничитель допускает один запрос одновременно на процесс и минимум 5 секунд
между началами запросов; за несколько процессов/других клиентов той же организации
он не отвечает. Ошибки квоты также обрабатываются агентом.

## Groq HTTP 429

429 означает ограничение квоты Groq. Приложение различает TPD/TPM (токены за
сутки/минуту), RPD/RPM (запросы за сутки/минуту), ITPM/OTPM и показывает
числовой `Retry-After`, если он есть в ответе. Неизвестный тип остаётся неизвестным;
сырой текст ошибки провайдера не показывается.

При диагностике 27.10.2026 реальный запрос со схемами инструментов получил TPD:
лимит 200 000 токенов, использовано 197 633, запрошено 2 689. Остаток 2 367
не покрывал запрос, хотя минутная квота была свободна. Короткая техническая
проверка в тот же период проходила: она требует меньше токенов и не подтверждает
наличие квоты для полного подбора. Groq указал `Retry-After: 140`. Это время до
следующей попытки, а не обещание полного восстановления суточной квоты.

Пока действует `Retry-After`, CLI не отправляет новые генерации и проверки связи,
а веб-версия отклоняет действия до подключения к MCP. Пауза общая для браузеров
одного процесса; история и найденные результаты остаются раздельными. После паузы
нужно вручную нажать «Продолжить запрос» (`/retry` в CLI). Результаты незавершённого
хода хранятся 5 минут; после этого поиск начнётся заново. Автоматических повторов нет.

Лимиты действуют на организацию: локальный агент, облачный сервис и Eval расходуют
общую квоту при использовании одной организации Groq. «Новый диалог» и новый ключ
в той же организации её не восстанавливают. На бесплатном тарифе нужно дождаться
пополнения и разнести прогоны Eval и демонстрацию по времени. Точные лимиты
смотрите в [Groq → Limits](https://console.groq.com/settings/organization/limits).
Смена тарифа или модели приложением автоматически не выполняется.

## Как устроена память

`st.session_state` содержит отдельный `WebMemory` и видимую переписку для каждого
сеанса. В нём нет ключей, клиентов HTTP, MCP-сессий или event loop. Каждое действие
создаёт и закрывает async-ресурсы в одном `asyncio.run`. История и незавершённый
ход переносятся в новый экземпляр агента; счётчики usage сохраняются отдельно.
Общими являются только блокировка и числовое состояние квоты. Maps Content не
кэшируется через `st.cache_data` или `st.cache_resource` и не пишется в файлы.
Это относится к приложению; автоматический кэш Groq для GPT-OSS существует
независимо от кэшей Streamlit. Состояние окон/пауз квоты разделено по моделям.
Обновление вкладки/перезапуск сервиса может очистить историю. Это учебный MVP
без аккаунтов, постоянной БД и распределённого управления нагрузкой.
