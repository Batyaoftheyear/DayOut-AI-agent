# GPT-OSS 120B через Groq

27 октября 2026 года пользователь выбрал `openai/gpt-oss-120b` после ошибки TPD
у Qwen. Провайдер и ключ Groq сохраняются; платные услуги не подключаются.

## Настройка

В локальном `.env`:

```dotenv
GROQ_MODEL=openai/gpt-oss-120b
```

Перезапустить CLI/Streamlit. Для публичного сайта отдельно изменить `GROQ_MODEL`
в Streamlit Cloud → Settings → Secrets на то же значение. Ключи не менять.
После смены модели начать новый диалог; старый незавершённый ход не использовать.
Для явного возврата доступна `qwen/qwen3.8-27b`; автоматического fallback нет.

## Изменения агента

- CLI и веб принимают оба указанных ID; остальные модели не допускаются.
- GPT-OSS получает `reasoning_effort=low` и `include_reasoning=false`.
  Параметр `reasoning_format` одновременно не отправляется. Скрытые reasoning
  tokens всё равно расходуют квоту и входят в API usage.
- Из ответа провайдера передаются только `role`, `content`, `tool_calls`.
  Поле reasoning не показывается и не добавляется в историю.
- Протокол вызова MCP, проверка JSON Schema, ссылки, ручное продолжение и
  ограничения числа шагов сохранены.
- Локальные индексы `[0]`, `[1]` в summary связываются с метаданными places
  того же ответа до отправки модели. Итоговые числовые ссылки без адреса
  отклоняются с одной попыткой исправления; источники не угадываются.
- Для GPT-OSS `cached_tokens > 0` не считается ошибкой; Qwen сохраняет прежнюю
  защиту от неожиданного кэша. Usage учитывает полные входные/выходные токены,
  без попытки самостоятельно вычислять списание квоты или стоимость.
- Общий ограничитель сайта хранит отдельные окна и паузы по моделям. Переключение
  на GPT-OSS не переносит TPD-паузу Qwen; возврат на Qwen помнит её паузу.

## Кэширование и пределы совместимости

Groq автоматически кэширует GPT-OSS в оперативной памяти; отключить этот кэш
параметром запроса нельзя. Global ZDR относится к удержанию данных для мониторинга
и не является доказательством отключения prompt caching. Приложение не добавляет
собственный общий кэш результатов Maps и не сохраняет их в файлы.

Документация Maps Grounding Lite требует, чтобы Maps Content не кэшировался и
не сохранялся выбранной LLM. Поэтому технически успешные тесты GPT-OSS не
подтверждают совместимость этой конфигурации с данным требованием Google.
Этот вопрос остаётся открытым; не следует заявлять для GPT-OSS «кэша нет» или
«полная совместимость Maps подтверждена». Предыдущая аргументация выбора Qwen
на GPT-OSS не переносится.

## Проверки

Короткий технический запрос GPT-OSS с существующим ключом получил HTTP 200.
Реальная проверка искусственного инструмента выполнила вызов с валидными
аргументами. Первая попытка не прошла проверку финального русского текста/кода;
отдельный ручной повтор вернул ожидаемый код и русский текст. Проверка не
использует Maps Content и не является Eval пользовательских рекомендаций.

Первый двухходовый CLI smoke-тест с реальным MCP завершился: один поиск,
затем уточнение с сохранённой ссылкой без нового поиска. Всего три обращения
к LLM, 5 474 входных и 217 выходных токенов API; время ходов 3,6 и 0,6 с.
Сырой ответ и данные мест в репозиторий не включены. Наблюдались сомнительные
географические уточнения; добавлено правило не выводить район/метро по одному
названию места. Полноценный Eval качества GPT-OSS ещё не проведён.

После исправления цитирования повторный живой тест через веб-адаптер завершился
за 3,7 с: один поиск, два обращения LLM, 3 445 входных и 159 выходных токенов.
Обе рекомендации имели непосредственные ссылки Google Maps; числовые индексы
в итоговый ответ не попали. Это локальный веб-адаптер, а не проверка публичного
сервера Streamlit Cloud после обновления.

Все 168 технических тестов в подготовленной копии публичного репозитория прошли,
включая GPT-OSS tool calling на искусственных данных, обработку cache hit,
скрытие reasoning, привязку источников и раздельные квоты моделей. Тесты не
заменяют Eval достоверности пользовательских рекомендаций.
