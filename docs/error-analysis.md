Обновлено: 27 октября 2026 года. Это журнал разработки по пользовательскому
выводу и техническим проверкам, а не завершённый Eval на фиксированном наборе.
Сырой лог, пользовательский запрос, ключи и Maps Content сюда не копируются.

## Проверки после изменений

Для веб-версии обнаружена отдельная причина постоянных ошибок MCP: локальный
Streamlit был запущен агентом разработки в сетевой песочнице. Повтор одного
обезличенного запроса в ограниченном процессе не подключался, вне песочницы —
проходил. Сервер перезапущен с доступом к сети; встроенный технический поиск
проверен прямо в браузере: получен завершённый ответ с двумя ссылками Maps.
Это исправление среды запуска, а не доказательство отсутствия других сетевых причин.
Диагностика MCP теперь различает ConnectError, ProxyError, ReadError,
RemoteProtocolError и типы таймаутов без вывода сырого исключения.

- `python -m pytest -q`: 128 passed, включая логику CLI, диагностику, квоты и продолжение хода.
- Реальная проверка Groq: GET списка моделей и POST генерации вернули HTTP 200.
- Новая команда /check проверена с реальным API: прошла. В ней только фиксированный
  технический текст без переписки и данных Maps.
- Пользовательский сценарий повторно во внешние API не отправлялся.
- Типы сетевых ошибок и 403 воспроизведены в локальных тестах через подмены.
- Настройки VPN/прокси пользователя не изменялись; TLS-проверка не отключалась.
- В локальном тесте обрыв после двух MCP-вызовов, /check и /retry: продолжение
  использовало оба результата без нового поиска. Счётчики хода сохранились, /check
  исключён из его usage. Повторная ошибка источника блокируется без третьей генерации.
- В реальном техническом поиске музея после изменений: один MCP-вызов, два обращения
  LLM, 4841 входной и 91 выходной токен, 2,5 с. Восстановление после обрыва проверялось
  локально; живой обрыв сети специально не создавался.
- Последняя живая проверка после изменений качества/ожидания не началась:
  сетевая ошибка при подключении к MCP до запуска агента. Новых успешных замеров
  этой версии нет. Предыдущие успешные проверки не доказывают текущую доступность.
- Локально проверены исправление обещаний, отсутствие подтверждения часов при
  неизвестном расписании, продолжение после таймаута/429, суммарное ожидание и
  отсутствие нового HTTP-запроса при исчерпании бюджета ожидания.

## Почему это ещё не Eval

Нет фиксированного набора пользовательских запросов с заранее заданной разметкой,
метрик качества до/после и повторных прогонов. Эти наблюдения следует использовать
при подготовке Eval из docs/plan.md. В итоговом README нельзя выдавать число
pytest-тестов за долю успешных пользовательских сценариев.
