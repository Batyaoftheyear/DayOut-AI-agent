# Спецификация DayOut

Обновлено: 27 октября 2026 года. Статус: реализован консольный агент Groq + MCP;
реальный полный цикл поиска и ответа подтверждён. Погода, маршруты, качество
планировщика, стабильность и UI ещё не подтверждены. Разработка идёт
последовательно от спецификации к проверке.

## Назначение и MVP

Русскоязычный AI-ассистент принимает описание досуга и предлагает 2–3 сценария
с реальными местами, адресами, объяснением выбора и ссылками Google Maps.
Учитываются бюджет, время, расположение, интересы и существенная для сценария
погода. Последовательность посещений проверяется через маршруты. Пользователь
может менять ограничения в текущем диалоге.

LLM должна сама выбирать инструменты, анализировать их ответы и сравнивать
варианты. Нельзя придумывать места, цены, часы работы, время в пути и наличие
билетов. Неизвестные цены обозначаются как неизвестные; оценка явно отделяется
от факта. Результаты инструментов тоже могут содержать AI-generated summaries.

Целевая цепочка: Streamlit → сессия → LLM с tool calling → Python MCP SDK →
Google Maps Grounding Lite → проверка результата → сценарии в UI.
Контекст хранится в текущей сессии; база данных, избранное, история и интерактивная
карта пока не требуются. Для курса позже нужны публичный репозиторий, хостинг,
README и интерактивная HTML-презентация с демонстрацией до 10 минут.

## Текущий объём

`mcp_check.py` и `groq_check.py` остаются отдельной диагностикой.
`agent.py` реализует ограниченный агентный цикл, `dayout.py` — консольный чат.
Фреймворки агентов и новые зависимости не добавлены. UI остаётся следующим этапом.

- Endpoint фиксирован: `https://mapstools.googleapis.com/mcp`.
- Транспорт: Streamable HTTP; авторизация: заголовок `X-Goog-Api-Key`.
- Секрет берётся из `GOOGLE_MAPS_API_KEY` либо `.env` рядом со скриптом.
- SDK фиксирован на `mcp==1.30.0`, поддерживаемой ветке v1 с `ClientSession`.
  Основная документация SDK уже описывает v2; миграция требует отдельного решения.
- `httpx` передаётся в транспорт с заголовками и таймаутом; REST API не используются.
- `initialize()` предшествует `list_tools()`; все страницы читаются до конца
  с ограничением в 20 страниц и обнаружением повторяющегося курсора.
- Имена и входные JSON-схемы выводятся только из ответа сервера.
- Из документации ожидаются `search_places`, `lookup_weather`, `compute_routes`,
  `resolve_names`, `resolve_maps_urls`; наличие проверяется реальным списком.
- Поиск формируется по объявленным полям схемы и валидируется через jsonschema.
  При несовместимой схеме вызова поиска нет.
- Один вызов `search_places`, без автоматических повторов; `--list-only` исключает поиск.
- Общая длительность ограничена; HTTP-ошибки, таймауты, сетевые и протокольные
  ошибки, MCP `isError` и пустой ответ приводят к ненулевому коду завершения.
- Значение ключа скрывается; тела исключений и traceback не печатаются.
- Ответы Maps не сохраняются в файлы и не включаются в тестовые фикстуры.

## Google Maps Content и выбор LLM

Официальная документация требует сохранять источники рядом с поддерживаемым
ими результатом; для поиска используются возвращённые ссылки
`places.googleMapsLinks.placeUrl` и атрибуция Google Maps. В будущей UI источники
должны следовать сразу за соответствующим текстом и быть доступны за одно действие.
CLI сохраняет полный ответ для диагностики; требования отображения будущего UI
проверяются отдельно.

До подключения LLM необходимо проверить условия провайдера: Maps Content не
должен сохраняться, кэшироваться или использоваться для обучения/улучшения
модели. Самого заявления «не обучаем» недостаточно для проверки хранения.
Предварительный кандидат: `qwen/qwen3.8-27b` через бесплатный Groq API;
платный тариф не подключён. 26 октября 2026 года groq_check.py подтвердил
авторизацию, наличие модели и один цикл вызова искусственного инструмента
с финальным русским ответом. Это не сравнение моделей и не Eval планировщика.
27 октября пользователь подтвердил включение Global ZDR. Проверенная документация
Groq перечисляет только GPT-OSS-модели как поддерживающие prompt caching; Qwen
в список не входит. На этом основании выбранная конфигурация допущена к реальной
проверке. Код не может независимо подтвердить настройки аккаунта или отсутствие
кэша; при сообщении API о cached_tokens > 0 он останавливает ход.
Первый реальный агентный поиск выполнен, данные MCP переданы модели и получен
ответ со ссылкой из источника. Качество на наборе кейсов и достаточность квот
ещё предстоит оценить. Бесплатный API уже возвращал HTTP 429 на уточнении.
После добавления ожидания квот повторный двухходовый тест прошёл: первый ход
вызвал search_places, уточнение использовало контекст без нового MCP-вызова.
Время — 3,2 и 42,8 с соответственно; во втором ходе ожидание токенового окна.
54 локальных технических теста прошли 27 октября. Это не полный Eval.
Бесплатный тариф нельзя автоматически считать совместимым с Maps Content.

Обновление 27 октября: по запросу пользователя добавлена техническая поддержка
`openai/gpt-oss-120b` для CLI и веб-адаптера. Это модель с неотключаемым кэшем
Groq; прежний выбор Qwen нельзя считать обоснованием совместимости GPT-OSS
с ограничениями Google Maps. Состояние квот разделено по моделям, автоматической
смены модели нет. Настройки, проверки и открытый вопрос кэширования описаны
в [model-migration.md](model-migration.md).

## Ограничения консольного агента

- Пять разрешённых инструментов, схемы из list_tools(), валидация перед вызовом.
- Описания схем сокращаются для модели; правила валидации сохраняются.
- До 8 попыток MCP-вызова за ход, 120 секунд на попытку обработки; без автоматических
  повторов HTTP- и сетевых ошибок. Лимит шагов/вызовов сохраняется при ручном продолжении.
- Два последних завершённых ответа и недавние данные инструментов в памяти;
  исходные пользовательские условия сохраняются до 12 000 символов без пересказа.
  Старый протокол tool_calls не передаётся повторно. Добавление хода атомарно.
- Ссылки передаются модели короткими метками и разворачиваются приложением;
  неизвестные метки блокируются. Поиск по умолчанию — 3 результата, если это
  поддерживается схемой; явный размер сохраняется. Ответ ограничен 1600 токенами.
- Язык search_places по умолчанию ru при поддержке languageCode/language_code
  реальной схемой. Явный язык сохраняется. Часы работы запрашиваются в textQuery;
  информация о местах преимущественно приходит в summary, а не отдельным расписанием.
- При известных заголовках квот Groq выполняется ожидание до следующего окна,
  если приблизительная оценка запроса больше оставшегося лимита. Это не точный
  токенизатор и не гарантия отсутствия HTTP 429.
  Суммарное автоматическое ожидание ограничено 45 секундами за попытку; при нехватке
  бюджета запрос не отправляется, ход можно продолжить через /retry после паузы.
- Расход показывается из usage Groq по запросам и суммарно за ход; неизвестный
  расход явно обозначается. Оценка для ожидания калибруется по фактическим usage.
- Ответы MCP используются как недоверенные данные. Исполнение произвольного
  кода, неизвестных инструментов и внешних JSON Schema refs запрещено.
- Источники извлекаются из метаданных ответов. Выдуманные URL блокируют ответ.
  Модель получает список допустимых меток источников. Для неверной метки/URL допускается
  одна попытка исправления в рамках хода; повторно неверный ответ блокируется.
  Её же используют эвристики фоновых обещаний, неподтверждённых часов и минут пути.
  Проверяется наличие признаков расписания в успешных MCP-summary, но не соответствие
  каждой фразы конкретному месту/дню. Это не полная семантическая верификация.
  Остальные фактические утверждения контролируются инструкциями модели и будущим
  Eval, не считаются автоматически верифицированными.
- CLI использует реальные сервисы, расходует квоты, не хранит диалог в файлах.
- Автозамены модели/тарифа нет. Нужна отдельная проверка перед сменой модели.
- После сетевого сбоя Groq или HTTP 401/403 CLI приостанавливает запросы до
  успешного /check. Команда /check не отправляет переписку. При сбое обращения к Groq
  незавершённый ход остаётся отдельно в памяти; /retry в течение 5 минут продолжает его
  с полученными MCP-результатами. Новый вопрос, /reset, перезапуск или истечение срока
  исключают продолжение; тогда повтор запускает ход заново. Сбой MCP не сохраняет
  неполный протокол. Пустой ввод и известные строки логов игнорируются.
  Сохранение на границе LLM также действует при общем таймауте, нехватке бюджета
  ожидания и HTTP 429. При наличии поиска выводятся кандидаты из метаданных без
  непроверенных описаний; готовым результатом они не считаются.
- После разбора пользовательского вывода 27 октября число локальных тестов — 68,
  все проходят. Диагностика Groq сейчас успешна; причина прошлых отказов не установлена.
  Инструкции по бюджету и уточнениям усилены, но качество требует Eval.

Журнал ошибок и границы проверок: [error-analysis.md](error-analysis.md).
Оптимизация расхода: [token-usage.md](token-usage.md). После неё 78 тестов прошли;
реальный короткий поиск и уточнение завершились без ожидания квоты. Это не полный Eval.
После исправления восстановления хода и источников: 96 технических тестов прошли.
После исправлений качества и квот — 128 тестов проходят. Живая проверка этой версии
не завершилась из-за сетевой ошибки при подключении к MCP.

`compute_routes` предоставляет расстояние и длительность пешего/автомобильного
маршрута, но не пошаговую навигацию или информацию о трафике в реальном времени.
Для тестов используется Demo Key; подключение биллинга требует согласия пользователя.

## Критерии приёмки текущего этапа

1. Локальные тесты проходят без ключа и сетевых запросов.
2. Без ключа понятная ошибка до подключения.
3. С действительным Demo Key получены и выведены реальные JSON-схемы.
4. Выполнен один `search_places` по музеям Москвы без `isError`; вручную проверены
   места, источники и содержимое ответа.
5. Ошибки не раскрывают секреты, лишних повторов нет.

Получение схем и успешный поиск подтверждены присланным пользователем выводом:
пять мест, идентификаторы, координаты, источники и `isError: false`.
Независимая проверка каждого места, адресов и актуальности описаний не проводилась.
Технические тесты: 19 прошли 26 октября 2026 года; они используют подмены.

## Готовность к сдаче курса

Сдать нужно работающий MVP целиком: LLM + реальный MCP + пользовательский
интерфейс + доступный хостинг, публичный README, Eval с разбором ошибок,
интерактивную HTML-презентацию и демонстрацию до 10 минут.
План приёмки и ограничения MVP уточнены в `docs/plan.md`, сопоставление с
рубрикой — в `docs/course-review.md`. Итоговый README должен быть самодостаточным:
ссылки на эти документы дополняют, но не заменяют обязательные разделы.
