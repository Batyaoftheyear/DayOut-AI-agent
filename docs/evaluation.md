## Что проверялось

Живой Eval проходит через `web_backend.run_action`: используются настоящие запросы к модели и Google Maps MCP. Это проверка того же агента, который работает в интерфейсе, но не нагрузочный тест публичного хостинга.

- **Основной набор:** 30 сценариев, 37 пользовательских реплик, один полный прогон итоговой версии. 20 сценариев применялись при разработке, 10 отложены для итоговой проверки.
- **Дополнительный набор:** 6 сценариев, 24 реплики. В него входят цепочка поиск → ссылка → Place ID → маршрут, бюджет на человека, изменение числа участников, отказ выдумывать место, относительная дата, диалог из 15 реплик и запрос о прогулке на юге Москвы.
- **Искусственные отказы:** 4 сценария без внешних API — пустой результат, ошибка соединения, отказ доступа и ограничение частоты.

Наборы проверяют пять инструментов и разные задачи: кафе, рестораны, музеи, прогулки, семейный досуг, смену района и категории, бюджет, погоду, маршруты, названия и ссылки. Это ограниченный набор характерных сценариев, а не проверка всех возможных формулировок.

Каждый сценарий начинается с новой памяти; его реплики используют общий диалог. Дата прогноза зафиксирована как 03.11.2026. Относительное «завтра» вычисляется от даты запуска по часовому поясу Москвы. При повторении эксперимента следует выбрать актуальную дату в пределах доступного прогноза.

## Критерии

Автоматические проверки устанавливают:

1. Получены ли все ответы сценария.
2. Вызваны ли нужные инструменты и соблюдены ли запреты на поиск, погоду или маршрут.
3. Корректны ли аргументы и фактические дата/час прогноза.
4. Сохранены ли сумма, единица бюджета и число людей в контрольных репликах длинного диалога; не вернулась ли отменённая сумма.
5. Есть ли ожидаемые сведения и отсутствуют ли запрещённые фрагменты или лишние ссылки.

Содержание оценивает отдельный запрос к Alice Flash, которому передаются запрос пользователя, ответ агента и исходные данные инструментов в памяти. Критерии: соответствие задаче, ограничениям и источникам; честность; выбор инструментов; при необходимости — ведение диалога, уточнения и обработка отказов.

**Техническое завершение** означает, что получены все ответы. **Успех по качеству** требует прохождения всех автоматических проверок и всех оценок содержания. Неудачная первая попытка не заменяется удачным повтором. Отказ внешнего сервиса остаётся неуспехом сквозной системы, даже если агент корректно объяснил проблему.

В длинном разговоре проверка продолжается после обработанной ошибки инструмента, если пользователь получил ответ. Это позволяет отдельно измерить непрерывность разговора и успешность конкретных действий. Неисправленная ошибка агента или транспорта прекращает сценарий.

## Разбор ошибок

| Ошибка | Причина | Изменение |
| --- | --- | --- |
| «В каком городе?» после фразы «на юге Москвы» | Планировщик заполнял район, но оставлял город пустым | Явное название Москвы учитывается в разных падежах; исходная формулировка включена в E05 |
| Текст `[search_places: ...]` вместо действия | Модель могла выбрать обычный ответ вместо вызова | Для обязательного действия задаётся `tool_choice`; псевдовызов в тексте отклоняется |
| Поиск «свидания» вместо ресторанов | Смешивались тип места и цель посещения | Категория и цель разделены; явно названная категория сохраняется |
| Место объявлено в 15 минутах при более длинном маршруте | Проверка ссылки на маршрут не охватывала ссылку на само место | Длительность связывается с кандидатом и сравнивается с пределом пользователя |
| Новый поиск не выполнялся после «пока не ищи» | Временный запрет переносился на следующие реплики | Новая явная просьба найти места разрешает поиск, сохраняются только применимые условия |
| Отклонялся поиск после отдельных вопросов о погоде/маршруте | Проверка координат не учитывала сохранённые сведения последнего поиска мест | Допустимые координаты проверяются и по этому сохранённому результату |

Остаются ошибки описаний и выбора действий, а также зависимость от сети и квот. Особенно сложна единая просьба одновременно подобрать прогулку и кафе, проверить погоду и связать точки маршрутом: такой составной сценарий не объявляется устойчивым. Каждый из инструментов отдельно прошёл живую проверку. Дневная квота Demo Key ограничивает доступность сайта; для постоянной нагрузки нужен подходящий ключ Google Maps. После настройки нового ключа локальные запросы Maps проходят. Сетевые отказы и неуспехи предыдущих попыток включены в результаты.

Цены — отдельное ограничение источника: в используемой схеме поиска нет фильтра по среднему чеку и обязательных цен меню. Условие «3000 ₽ на двоих» сохраняется, но не превращается в доказанную стоимость. Положительный ответ о бюджете допустим только при достаточных данных; иначе стоимость обозначается как неподтверждённая.

## Ограничения оценки

Рецензент — та же модель отдельным запросом. Это **LLM-оценка**, а не независимая человеческая разметка. Она может разделять ошибки агента, быть чрезмерно строгой и выдавать неточный краткий код причины. Оценки сохранены без выборочного повышения; коды не считаются доказанным диагнозом.

Поле отчёта `manual_scores` исторически используется и для оценок модели. Метод определяется по `metadata.review_method=llm_assisted_same_model` и `model_review`. Выборочная проверка отдельных фактов не равна полному экспертному аудиту.

Проверяются конкретная версия, модель `latest`, ключи и доступность сервисов в день измерения. Обновления модели или Maps могут изменить результат. Проверки Python защищают от части известных ошибок, но не заменяют оценку фактического содержания каждого нового ответа.

## Расходы и сохранённые данные

По известным токенам основной прогон — **около 30,97 ₽** с модельной оценкой. Семь опубликованных оценочных наборов в таблице вместе — **около 81,96 ₽ по учтённому usage**. У 5 запросов usage отсутствует, поэтому полный расход не установлен. Это расчёт без скидок за кэш, не счёт провайдера; предыдущие разработческие запуски и расходы Maps в эту сумму не входят.

Расчёт: `(входные токены × 0,10 + выходные × 0,20) / 1000`, включая рецензента. Все входные токены оценены по полной ставке, без скидок за кэш. Если API не вернул usage, полная стоимость не вычисляется; отдельно можно показать расход по известным токенам. Это не выписка биллинга, расходы Google Maps не включены. [Тариф Flash](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing), проверен 02.11.2026.

В отчётах нет сырых ответов Maps, описаний мест, адресов, Place ID, ссылок выдачи и contentToken. Сохраняются метрики, категории ошибок и условия, заданные пользователем. Исходные данные доступны рецензенту временно в памяти. `--inspect` показывает их в терминале; такой вывод нельзя считать обезличенным отчётом и не следует сохранять или публиковать как лог.

## Воспроизведение

Подготовить окружение и ключи по [README](../README.md). Команды live выполняют платные запросы модели и расходуют отдельную квоту Maps. Для нового прогона нужно выбрать новое имя файла; перезапись первичных результатов запрещена.

```powershell
# Без API
python -m pytest -q
python eval_runner.py --list
python eval_runner.py --mode simulated --split all --output eval/results/offline-new.json

# Все 30 основных сценариев: один полный прогон
python eval_runner.py --mode live --split all --repeat 1 --visit-date YYYY-MM-DD --max-live-turns 37 --llm-review --input-rub-per-1k 0.1 --output-rub-per-1k 0.2 --output eval/results/main-new.json

# Дополнительный набор, включая 15 реплик
python eval_runner.py --cases eval/extended_cases.json --mode live --split all --visit-date YYYY-MM-DD --max-live-turns 24 --llm-review --input-rub-per-1k 0.1 --output-rub-per-1k 0.2 --output eval/results/additional-new.json
```

Заменить `YYYY-MM-DD` на дату визита; для сценария «завтра» — завтрашний день Москвы. Для отдельного теста исходного запроса: добавить `--case E05` к команде дополнительного набора. Для повторов — `--repeat`, увеличив предел реплик; повторные прогоны должны учитываться явно.

```powershell
# Пересчитать опубликованную сводку без API
python -m eval.final_report --followup eval/results/final-followup-r12-2026-11-02.json --followup eval/results/long-dialogue-repeat-r12-2026-11-02.json
```

У скрипта сводки есть аргументы `--main`, `--additional`, `--output` для других файлов. Он проверяет одинаковую версию кода и полноту заданного покрытия.
