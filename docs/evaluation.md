# Eval DayOut: методика, измерения, продолжение

Дата: **30.10.2026**. Модель: Alice AI LLM Flash `latest`, Yandex AI Studio.
Измеренный runtime: `2026-10-30-r6`, commit `90aef8f`, тег `eval-r6-2026-10-30`.
SHA-256: `91f9a103dcd9a3c0b06cfcca187689fb84f6ea5062abf23a62d112cfca33a439`.

Живые проверки выполнены через `web_backend.run_action`: настоящий агент, Yandex API и Google Maps MCP. Это локальный веб-адаптер, не нагрузочное измерение публичного Streamlit. Браузерные проверки интерфейса хранятся отдельно. Обычный pytest использует подмены API и не измеряет качество рекомендаций.

Технические проверки: 234 теста пройдены; `pip check` без конфликтов. [Четыре искусственных сценария](../eval/results/offline-release-2026-10-30.json) прошли. [Публичный интерфейс](../eval/results/cloud-release-2026-10-30.json) загрузил r6 и кнопку презентации, без отправки генерации. [Публикация HTML/PDF](../eval/results/presentation-public-2026-10-30.json) проверена отдельно. Эти проверки не подтверждают доступность поиска при исчерпанной квоте Maps.

## Дизайн эксперимента

- [cases.json](../eval/cases.json): 30 live-сценариев, 37 пользовательских ходов. 20 development / 10 holdout. План — 3 повтора на сценарий, 90 попыток / 111 ходов.
- [extended_cases.json](../eval/extended_cases.json): 5 дополнительных сценариев / 23 хода. Положительное разрешение реальных ссылок, бюджет на человека и изменение числа людей, отказ выдумывать данные, относительная дата, 15-ходовый диалог.
- 4 simulated-сценария: искусственные ошибки и проверки поведения без внешних сервисов.

Сценарий — один новый диалог; внутри него все реплики используют одну память. Между сценариями память новая. Первый неуспех сохраняется, его не заменяют удачным повтором. Повторы имеют явный номер. Проверки holdout не использовались для последующего изменения r6. Он выполнен лишь частично, поэтому оценка обобщения пока невозможна.

Параметры погоды проверяются по фактическим запросам инструмента. Дата визита в первых прогонах — 31.10.2026. План и дата сервера используют Europe/Moscow. При продолжении в другой день нужна новая `--visit-date`; сравнение станет междневным, а не строго одинаковым экспериментом.

## Как оценивается ответ

Автопроверки: завершились ли все реплики; вызваны ли обязательные и отсутствуют ли запрещённые инструменты; успешны ли нужные инструменты; корректны ли аргументы; есть ли ожидаемый текст/сумма; нет ли запрещённых фрагментов; число ссылок; соответствуют ли `date`/`hour` условию.

Содержание проверяет отдельный платный запрос Alice Flash по исходным данным MCP: relevance, constraints, grounding, honesty, tool_choice; для подходящих кейсов — dialogue, clarification, controlled_behavior. Состав критериев и ожидаемое поведение зафиксированы в датасете. Все критерии имеют равный обязательный статус: для успеха нужны все auto-checks и все оценки pass.

Это **LLM-assisted review той же моделью**, а не человеческий gold standard. Рецензент может разделять ошибки агента; короткие коды причин иногда неточно объясняют провал. Сохраняется исходная оценка, её не исправляют ради метрики. Выборочно сверены привязка ссылок, бюджет и несколько числовых фактов в B02, C02, T01 и E01. Эти частичные проверки не заменяют полного независимого аудита и не переопределяют модельные оценки.

Поле `manual_scores` исторически используется как контейнер оценок. Источник оценки определяется по `metadata.review_method` и `model_review`; в данном прогоне это `llm_assisted_same_model`.

| Метрика | Значение |

| Различных сценариев / план | **23 / 30** |
| Пользовательских ходов с попыткой / ответом | 45 / 40 |
| Технически завершённых сценариев | **34 / 39 (87,2%)** |
| Пройдены все критерии, включая инфраструктуру | **27 / 39 (69,2%)** |
| Ошибки качества | 9 |
| Внешние отказы | 3: сеть ×1, Maps quota ×2 |
| Успех без инфраструктурных отказов | 27 / 36 (75%) |
| Медиана / p95 времени хода | **15,45 / 28,42 с** |
| Запросов LLM агента / рецензента | 151 / 34 |
| Входных / выходных токенов вместе | 339 882 / 14 820 |
| Оценка расходов вместе | **36,9522 ₽** |

Development: 36/60 попыток, 25 pass, 9 fail, 2 infra. Holdout: 3/30 попытки, 2 pass, 0 fail, 1 infra. **100% в двух оценённых holdout-попытках нельзя трактовать как точность на holdout.**

Завершение означает получение всех ответов без инфраструктурного отказа, а не выполнение задачи. Отказ инструмента считается внешним неуспехом сквозного сервиса даже при вежливом ответе модели. Время хода включает API и внутренние исправления, но исключает паузу между кейсами; p95 — наблюдаемый квантиль малой выборки без доверительного интервала.

Прогон оборван из-за **суточной квоты Google Maps Demo Key**: MCP вернул HTTP 429 с дневным ограничением. Точный момент сброса и размер квоты из ответа не установлены. Документация Google описывает возобновление на следующий день. Пополнение Яндекса не меняет Maps-квоту. По решению владельца оставшиеся **51 попытка** отложены до сброса.

| E03: предложение выдумать место | Пройден |
| E04: «завтра» | Пройден |
| L01: 15 ходов | Получено 11 ответов, затем runner завершил сценарий на ошибке погоды |

Дополнительный набор: 5 попыток, 4 завершённых сценария, 3 pass, 1 fail, 1 infra; 19 ответов на 19 предпринятых ходов. Длинный L01 здесь закончился не падением процесса, а остановкой runner после обработанной ошибки инструмента.

Для различения этих причин выполнен отдельный `eval.dialogue_stress`, который продолжает после корректно обработанной ошибки инструмента. В этом запуске получены **3 ответа**, на 4-м ходе агент не выполнил обязательный поиск и остановился после проверки. Это ошибка логики агента, не исчерпание баланса. **Успешного 15-ходового прогона нет.** Его необходимо повторить после исправления и восстановления квоты; новый runtime измерять отдельной версией.

Все пять инструментов реально вызывались в основном и дополнительном наборе вместе. Не все запланированные варианты (в частности итоговые T02/T03 для текущей/почасовой погоды) успели выполниться.

## Разбор ошибок

| Случай | Наблюдение | Вывод и дальнейшее действие |
| --- | --- | --- |
| B01, C03, D01 | Ответ получен, часть grounding-оценок fail | Проверка допустимого URL недостаточна для проверки всех фактов; нужны более строгая привязка утверждений к данным и независимая сверка |
| B03 ×2 | План уточнения вместо нужного поиска прогулки | Ошибка маршрутизации задачи; дополнительное пополнение не поможет |
| T07 | Нет всех обязательных инструментов комбинированного плана | Необходимо улучшить исполнение плана и проверить условные зависимости |
| B07 ×2 | Ошибка аргументов, задача у станции не завершена | Строгая близость не пройдена. Проверки предотвращают часть неверных рекомендаций, но сами по себе не решают запрос |
| A03 | Сетевой отказ | Учитывается во внешних неуспехах; не удаляется из отчёта |
| D04/D03 | Maps HTTP 429 | Внешняя дневная квота; не модель и не Яндекс-баланс |
| L01 stress | Не вызван обязательный `search_places` | Автоматический выбор инструмента иногда даёт обычный текст вместо действия. Возможное исправление — управляемый tool_choice, с отдельной проверкой зависимых шагов |

Ранее исправлены повторяющиеся tool-call ID, формат `places/ID`, передача даты/часа, сохранение суммы при изменении числа людей, источники текущей задачи и ограниченная память последнего поиска. Проверены тестами; итоговый Eval показывает, что это не устранило все ошибки качества.

Запросы погоды с явным `languageCode` при диагностике текущего ключа давали отказ доступа, без поля — проходили. Это установленный факт конкретной интеграции, не общее утверждение о поддержке русского языка Google Weather.

## Расходы и данные

Все сохранённые прогоны за 30.10 (разработка r4/r5, preflight, r6, стресс) — **113,3906 ₽** по usage. Только дополнительные r6 — 14,3744 ₽, отдельный стресс — 1,4982 ₽. Список файлов и арифметика: [final-summary](../eval/results/final-summary-2026-10-30.json). Не суммируйте сводку повторно с её исходными файлами.

Расчёт: `(вход × 0,10 + выход × 0,20) / 1000`, включая LLM-рецензента. Все prompt-токены оценены по полной ставке без скидок за кэш и tool-токены. Это консервативный ориентир по тарифу Flash, не счёт провайдера и не показание остатка баланса. Расход Google не включён. Диагностические вызовы прошлых дат в эту сумму не входят.

Сырые ответы, адреса, описания, Place ID, ссылки выдачи и contentToken в отчёты не записываются. Рецензент получает доказательства временно в памяти. `--inspect`/`--spot-check` показывают их в терминале, поэтому не следует перенаправлять этот вывод в файлы или публиковать логи.

## Воспроизведение

Подготовить окружение и ключи по [README](../README.md), проверить доступность сервисов. Обычный запуск создаёт новый файл и отказывается перезаписывать старый.

```powershell
# Список сценариев — без расходов
python eval_runner.py --list
# Четыре искусственных отказа — без расходов
python eval_runner.py --mode simulated --split all --output eval/results/offline-new.json
# Новый полный development: 20 сценариев × 3 (платно, расходует Maps)
python eval_runner.py --mode live --split development --repeat 3 --visit-date YYYY-MM-DD --max-live-turns 72 --llm-review --input-rub-per-1k 0.1 --output-rub-per-1k 0.2 --output eval/results/development-new.json
# Holdout после заморозки runtime — отдельно
python eval_runner.py --mode live --split holdout --repeat 3 --visit-date YYYY-MM-DD --max-live-turns 39 --llm-review --input-rub-per-1k 0.1 --output-rub-per-1k 0.2 --output eval/results/holdout-new.json
```

`YYYY-MM-DD` нужно заменить на актуальную дату визита, например завтра в пределах доступного прогноза. Для сохранения оригинальной версии — checkout тега. Флагов расходов по умолчанию нет: команды live выполняют платные запросы.

### Продолжить оставшиеся r6 после сброса квоты

Новый модуль продолжения не меняет измеренный runtime. Он проверяет SHA кода и датасета, сохраняет все старые попытки (включая fail), выполняет только ещё не начатые пары `(repeat, case_id)`. Изменение runtime требует нового Eval, продолжить старый нельзя.

```powershell
# Только посмотреть очередь: 24 development, без API
python -m eval.continue_run --parent eval/results/release-development-2026-10-30.json --dry-run
# После восстановления Maps; заменить YYYY-MM-DD, выбрать новые имена файлов
python -m eval.continue_run --parent eval/results/release-development-2026-10-30.json --visit-date YYYY-MM-DD --output eval/results/development-resumed.json
python -m eval.continue_run --parent eval/results/release-holdout-2026-10-30.json --visit-date YYYY-MM-DD --output eval/results/holdout-resumed.json
```

В holdout осталось 27 попыток; всего очередь содержит 51 попытку / 64 хода. Невыполненные хвосты уже проваленных сценариев не перезапускаются. Лимит одного продолжения по умолчанию 100 ₽ и 80 новых ходов, контролируется между ходами. Отчёт продолжения **уже включает родительские строки и стоимость**: нельзя суммировать его с родителем. Разные даты запуска сохраняются в метаданных и строках новых попыток.

```powershell
# Длинный диалог: платный отдельный прогон; старый файл не перезаписывается
python -m eval.dialogue_stress --visit-date YYYY-MM-DD --output eval/results/dialogue-stress-new.json
# Пересчитать исходную опубликованную сводку, без API
python -m eval.final_report
```
